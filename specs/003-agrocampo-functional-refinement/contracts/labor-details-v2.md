# Contract: Complete Agricultural Records / Labor Details v2

**Extends**: Módulo 002 `local-write-contract.md`.

## Command Envelope

```text
RecordLaborCommand<TDetails> {
  commandId
  boundContext
  occurredAt
  type
  details
  notes?
}

CorrectLaborCommand<TDetails> {
  commandId
  originalLaborId
  expectedVersion
  occurredAt
  details
  notes?
}
```

Every command passes productive-domain validation before persistence. The backend parses numeric
text/units and returns field errors; invalid values are never coerced with `tryParse ?? 0`.

## Discriminated Inputs

| Type | Required | Optional when supplied/applicable |
|---|---|---|
| `fertilization` | method Manual/Foliar/Fertirriego, product, dose, unit | observations, method-specific fields defined by 003, related irrigation ID |
| `diseaseAndPestControl` | product, target/plague/disease, dose, unit | safety interval, observations |
| `cultivation` | performed work, observed state | variety, affected plants, observations |
| `sowing` / `pruning` | existing v1 fields | existing compatible optional fields |
| `harvest` | quantity, unit | quality, destination, work shift, observations |
| `other` | descriptive name, detail | observations |
| `soil` | at least one indicator with explicit unit | other indicators defined by 003, observations |
| `irrigation` | see `irrigation-drip-v3.md` | recommendation snapshot |
| `apiary` | see `apiary-operations-v2.md` | photos |

`cultivation` is new and does not replace/relabel inherited `sowing` or `pruning`.

## Details Envelope

```json
{
  "schemaVersion": 2,
  "type": "discriminator",
  "data": {},
  "contextCompleteness": "complete"
}
```

- Unknown fields/schema versions are retained byte-for-byte for forward compatibility.
- Omitted optional values remain absent/null, never zero, false or “normal”.
- Units are stored with values and normalized values only where an approved deterministic conversion
  exists.
- Observations are not used as a substitute for typed fields.

## Atomicity

One confirmation writes:

1. labor root with Sector/category/crop/season snapshot;
2. zero or one specialization row (soil, irrigation, production or apiary);
3. exactly one compound outbox operation.

Any failure rolls back root, specialization and outbox. A successful return is
`savedLocal(backupState: pending)`. Photo attachment occurs after the target event exists through
its own retryable state; failure to attach a photo does not roll back or corrupt the confirmed
event.

## Corrections

A correction creates a replacement with `supersedesLaborId`, marks the original corrected and
keeps both auditable. It never silently changes date, unit, category, crop or season. Optional
fertilization data added later uses this path.

## Detail/History

The public detail DTO returns all confirmed fields, units, omissions, context labels, version,
correction relation and sync state. Cosecha/production and every other specialization have one
`groupingKey = labor:<rootId>`.

## Forbidden Behavior

- No chemical recommendation is generated by phytosanitary save/detail.
- No fertilization dose is calculated without a defined, versioned rule.
- Apiary commands cannot enter vegetable detail types.
- Validation/storage errors cannot be collapsed into a generic success or silently cleared draft.

## Acceptance

A representative file-backed matrix covers every discriminator and the relevant required,
optional, null-vs-zero, invalid, correction, restart, compound rollback, outbox and full-detail
partitions.
